## 1. Question

(DEC-CON-006) Across real archive populations of software ecosystems (Debian, Ubuntu, Fedora, Arch and Alpine packages; crates.io crates; a seeded npm sample) and the program corpus, what are the distributions of the eight ResourceBudget quantities, and what benign false-refusal rate does each candidate default policy imply per population, per field and in total? (DEC-CON-001) Which allocation sites in production reader code are sized by values read from untrusted archive bytes, which budget field, fixed format bound or caller policy bounds each before allocation, and which candidate (new declared fields, caller-policy-only limits, a fixed format-bounds registry, an explicit hole-length bound) would close each gap?

## 2. Hypotheses

- **H1 (populations).** The bootstrap-generous status quo refuses fewer than 0.1% of population archives on every field except `max_metadata_bytes`, where the refusal onset is governed by entry count × path length; go-extract-style conservative defaults (100,000 files, 1 GB) refuse at least 1% of the Fedora or Debian populations (large packages such as kernels, firmware and TeX distributions).
- **H2 (percentile rule).** A policy set at twice the p99.9 of the fit half of every population refuses at most 0.1% of the check half of every population (split rule in section 5).
- **H3 (DEC-CON-001).** At least one allocation site sized from an untrusted field is covered by no declared budget field and only by a fixed constant or by nothing: expected classes are per-entry xattr/ACL/ADS item counts, sparse-map extent counts and hole logical lengths, preserved legacy source bytes counted inside `max_metadata_bytes`, and dictionary bytes.
- **H0 / falsification.** H1 falsified if the conservative candidate refuses under 1% everywhere; H2 if any population's check half exceeds 0.1%; H3 if every untrusted-sized site maps to a declared field checked before allocation.

## 5. Inputs and split rule

- Populations (public downloads, approved; pinned by URL, retrieval date, size and SHA-256 in `research/experiments/EXP-CON-006/populations.json`, bytes stored outside git under `/root/eb-research/cache/EXP-CON-006/`):
  - Debian 13 `Contents-amd64.gz`, `Contents-all.gz`, `Packages.xz` (main); Ubuntu 24.04 `Contents-amd64.gz` and `Packages.xz` (main, universe);
  - Fedora 44 `primary.xml.zst` and `filelists.xml.zst` (Everything);
  - Arch Linux `core.files.tar.gz` and `extra.files.tar.gz` (file lists, `%CSIZE%`, `%ISIZE%`);
  - Alpine 3.24 `APKINDEX.tar.gz` (main, community; sizes only);
  - crates.io database dump (`versions.csv`: `crate_size`; sizes only);
  - npm: 5,000 package names drawn with seed 16001 from the registry's public name list, latest version `dist.fileCount` and `dist.unpackedSize`, fetched at ≤ 5 requests/s.
- Derived per archive (package): entry count (files plus implied directories), total logical bytes (installed size), largest entry (where file sizes are listed: Fedora `filelists` lacks sizes, so not available there; recorded as missing), expansion ratio (installed / compressed), path depth (maximum components), estimated metadata bytes (model below), estimated Chunk count (files × E[Chunks per file] under the balanced chunker from the corpus-fitted size model; labelled `model-derived`).
- `metadata_bytes_model.py`: fits bytes-per-entry of the status-quo Manifest as a linear model in (path bytes, components, entry kind, metadata items) on the **tuning** corpus items' measured `metadata_bytes` (from EXP-PLANNER-001 or EXP-SCALE-003 section-byte censuses, whichever is committed first), with its residual distribution; applied to population archives as an estimate with prediction intervals.
- Split rule (tuning/validation analogue for external data): within each population, packages with SHA-256(name) first byte even form the **fit** half, odd the **check** half. Candidate values are computed on fit halves (plus corpus tuning items) only; H2 and the false-refusal curves are reported on check halves (plus corpus validation items).
- Static census input: `crates/entrybound/src/**` at `9e44608` (reader-reachable modules: `ecf/`, `eam/`, `archive/`, `random_access.rs`, `codec.rs`, `transform.rs`, `reconstruction.rs`, `jpeg_reconstruction.rs`, `legacy/`, `crypto/`).
- Held-out: none (section 15).

## 6. Environment and platform requirements

WSL Ubuntu 24.04 (Python 3.12 stdlib; `zstd`, `xz`; network for downloads). No timing, no privileges. Disk about 3 GB (population metadata). The static census needs a Rust parser: `alloc_audit.py` drives a small helper built in the harness workspace (`ebr-alloc-audit`, using the pinned `syn` crate) that emits candidate sites as JSON; classification is scripted where the size expression is a literal constant or a named budget comparison dominates it in the same function, and judgment otherwise (section 7).

```sh

/root/eb-research/target/harness/release/ebr-alloc-audit --src crates/entrybound/src --commit 9e44608 > research/normalized/EXP-CON-006/alloc-sites.jsonl

```

`candidate-rules.json` (committed with this protocol's first tooling commit, before any download) encodes section 4's rules. `policy_curves.py` writes, per candidate, population, field and half: refusal counts, `benign_false_refusal_fraction`, and the refusal attribution (which field refused first in the §11.5 check order). Classification of allocation sites: classes `declared-field-checked-before`, `fixed-format-constant`, `caller-policy-checked-before`, `decode-requirements-checked-before`, `checked-after-allocation`, `unbounded`; every non-scripted classification is written by one session and independently re-derived by a second session; disagreements are resolved by citing code lines and recorded.

## 10. Normalization and statistical analysis

- Populations are evaluation conditions (AGG-S, never averaged across ecosystems); the corpus arm is aggregated by EXP-CONF-007 under §4.9. False-refusal fractions are exact counts on the check halves with Clopper-Pearson 0.99 intervals reported descriptively; decisions use the T-20 floor semantics.
- Estimated quantities (metadata bytes, Chunk count) are reported with their model prediction intervals; a candidate whose verdict flips between the lower and upper prediction bound is flagged `model-dependent` for that population.
- DEC-CON-001 coverage: per candidate, the fraction of `unbounded`, `checked-after-allocation` and `fixed-format-constant` sites that the candidate would move to a checked-before class (formal counterfactual); new fields' own benign refusal where observable (xattr totals from F19 corpus items; preserved-source bytes from EXP-CON-007 conversion cells).
- The decision owner combines these with EXP-CONF-007's hostile-case refusal cost under R4-R10 (profile-independent policy decision; cost tiers: new declared fields T2-T4, policy-only T0-T1).

## 11. Practical-significance thresholds

T-20 as transcribed in `research/methods/thresholds.json` (`0.5/n_cases`, minimum-gain cap 0.25). Not restated.

## 12. Sensitivity analysis

(a) Split-rule arm: reverse fit and check halves; (b) population-inclusion arm: leave one population out when deriving percentile candidates; (c) multiplier arm: 1×, 2×, 4× around the percentile rules; (d) model arm: metadata-bytes estimate at the lower and upper prediction bounds; (e) time-limit arm for candidates with time budgets, reported as unmappable to the eight fields (no wire field exists).

## 13. Adversarial search and expected negative results

- `adversarial-search/`: search each population for the benign archives closest to each limit (top 100 per field) and inspect whether they are legitimate (named, cited packages) — these are the archives a default would break; search the code for allocation sites reachable only through rarely exercised features (legacy preservation, reconstruction regions, encrypted collections).
- Negative results worth recording: the status quo already refusing real packages; percentile rules that do not transfer across ecosystems; allocation sites that no candidate bounds.

## 14. Threats to validity

Package metadata approximates archives (installed trees, not the archives users would pack; no home-directory or dataset populations are public at scale, so those workloads are represented only by the corpus); estimated metadata bytes and Chunk counts are model-derived (prediction intervals and sensitivity (d)); npm sample is small relative to the registry; static analysis can miss dynamically sized allocations (mitigated by EXP-CONF-007's dynamic attribution, whose observed untrusted-sized sites must all appear in this census, a pre-registered consistency check); L7 exposure (conventions §1).

## 15. Phase D held-out placeholder

Population data are external and not part of the corpus split. The held-out evaluation of the selected default policy is EXP-CONF-007's R5 run on the frozen corpus held-out items; this experiment contributes no held-out run.

## 16. Cost and effort

Compute: downloads about 2 h, statistics about 2 h, static audit about 1 h. Disk about 3 GB. Agent effort: judgment for incumbent citations and non-scripted allocation-site classifications (with the second-session re-derivation); scripted otherwise.
