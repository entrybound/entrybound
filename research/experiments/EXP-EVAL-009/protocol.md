## Question

What does it cost to reproduce a decision-relevant result from the repository alone, and where does reproduction fail? The package candidates are: committed definitions plus hash pins plus data outside git (status quo); analysis-only regeneration; an independent clean-host rerun; a hermetic Nix environment; digest-pinned container images; an archived artifact bundle; third-party replication.

## Hypotheses and falsification

- **H1 (analysis-only).** Re-running `ebr verify-raw`, `ebr normalize` and `ebr report` from committed raw data at the recorded tool commit gives byte-identical normalized, table and figure outputs for 100% of committed experiments (§12.3 item 4). Falsified by any byte difference. Each difference is a §8.5 downgrade trigger for dependent numbers, and is recorded and fixed.
- **H2 (clean host).** On a freshly imported WSL distro, provisioned only from committed definitions, all 120 deterministic sample cells of the `spec.yaml` subset reproduce exactly (`artifact_sha256`, `output_bytes`, `roundtrip_ok`), with two exceptions: cells whose tool version drifted (apt) and items with `output_pin: null`. The REF-PROD `ebound` binary built with `--locked` on the clean host produces byte-identical `.eb` outputs on the 8 `harness-cli-parity.sh` cells. The binary's own bytes may differ, because they contain build paths; that is recorded and not claimed.
  - Falsified by any other mismatch. Each mismatch is classified as undocumented dependency, unpinned input, non-deterministic tool, or corpus drift.
- **H3 (instructions).** A clean-host operator following only `research/tools/README.md`, `research/baselines/README.md`, `research/corpus/methodology.md` and `PROGRESS.md` "How to resume" needs at most 3 undocumented steps. Falsified by more than 3; every undocumented step becomes a documentation defect.
- **H4 (hermetic).** At least 95% of the Nix derivations for the pinned incumbent tool set rebuild bit-identically (`nix build --rebuild`). Incumbent sizes under Nix-pinned versions differ from apt versions only where versions differ. Falsified by under 95%.
- **H5 (inventory).** At least one decision-relevant input class is non-redistributable, unpinned or non-bit-reproducible (`license.redistributable = false`, `output_pin = null`, cached-only upstreams). The bundle candidate therefore cannot be complete. Reported as counts and bytes.

## Measurement method and metrics

No Appendix A.2 metric applies (program-method evidence). Measures:

- M1: fraction of experiments whose regenerated outputs are byte-identical.
- M2: deterministic-cell agreement fraction, mismatch classes, undocumented-step count, operator wall time.
- M3: counts and logical bytes of non-redistributable, `output_pin: null` and cached-only-upstream items per split.
- M4: bundle bytes.
- M5: fraction of rebuild-identical derivations, and a size-difference table under Nix tool versions.

The M2 cell values are `artifact_bytes` and the repeat-hash check (§4.13) as defined in EXP-EVAL-001.

## Replication and adaptive rule

- M1 is exhaustive.
- M2 uses 2 repetitions per cell (§4.6 deterministic). A mismatch triggers a third repetition on the clean host only to classify it as tool non-determinism versus environment; that classification rerun is recorded.
- M5 rebuilds each derivation twice.

## Normalization

Per cell: equality of `artifact_sha256`, `output_bytes` and `roundtrip_ok`. No aggregation beyond fractions.

## Statistical analysis

Exact counts and fractions; no intervals. Pre-registered reading for DEC-ECO-081:

- A package candidate is **sufficient** for a result class if its arm reproduces every deterministic cell of that class, or classifies every mismatch as documented tool drift.
- **Necessary components** are the minimal set of candidates whose union is sufficient for all classes.
- Decision-grade timing is excluded from exact reproduction by nature. Its reproducibility criterion is the same-direction verdict under §4.1, which EXP-EVAL-005's environment arm provides.

## Practical-significance thresholds

Deterministic equality (tolerance 0; §4.13). No A.2 band is used.

## Sensitivity analysis

- M2 with and without drifted-tool cells.
- M3 per split, and per family at count level.

## Expected negative results worth recording

- apt tool drift between the original and clean installs (Ubuntu security updates), breaking bit-identical incumbent cells.
- Build-path-dependent `ebound` binary bytes.
- Corpus items that can no longer be fetched upstream (cached-only), which makes the SQ package incomplete without the cache.
- Nix derivations that are not rebuild-identical.

## Threats to validity

- The clean distro shares the Windows host, kernel and hardware, so it is "clean-environment", not "independent machine". Hardware-dependent effects cannot surface; this is recorded.
- The operator is an agent session, not an external team.
- The provisioning download cache (`/root/eb-research/cache`) is **not** copied, so network availability of upstreams is part of the test. Unreachable upstreams are recorded, not worked around.

## Platform requirements

Windows host (non-admin `wsl --import`), WSL2, network (approved downloads: Ubuntu WSL rootfs, apt, rustup, PyPI hashes, Nix), large storage on D: (about 60 GiB for the clean distro, 10 items and toolchains). Docker is BLOCKED.
