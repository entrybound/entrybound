# Deterministic ZIP export v1

Status: implemented and frozen as target profile `zip/portable-v1`.

## Entries and paths

The profile emits regular files and explicit directories in canonical EAM
LogicalPath order. Names are UTF-8, use `/`, set general-purpose flag bit 11,
and directories end in `/`.

The profile refuses backslash/colon ambiguity, Windows control/reserved/device
components, trailing dot/space, wildcard/metacharacter components, names over
65,535 bytes, and Unicode-lowercase-equivalent collisions. It never renames or
sanitizes a path.

## Content and compression

Each file is reconstructed directly from EAM ContentObjects and receives an
independently calculated CRC-32. Directories and empty files use STORE.
Non-empty files are encoded both as STORE and raw DEFLATE using pinned
`flate2 1.1.9`, level 6. DEFLATE wins only when its payload is strictly smaller;
STORE wins ties. ZIP data descriptors are never emitted because sizes and CRCs
are known before writing.

ZIP64 is selected exactly when an individual size or local offset needs the
32-bit sentinel, or when EOCD count/central-size/central-offset needs its
classic sentinel. ZIP64 extra values occur only for sentinel fields and in
specification order. The central directory and ZIP64 EOCD/locator are
deterministic.

## Metadata and timestamp contract

Unix creator attributes carry the exact current `core.executable` value:
regular mode is 0644/0755 and directory mode is 040644/040755. DOS directory
and archive attribute bits are also canonical.

Absent `core.mtime` is `LOSSY`: ZIP requires a local-header timestamp, so the
profile emits the deterministic construction value 1980-01-01T00:00:00 and no
extended timestamp. A present mtime emits:

- a deterministic UTC-derived DOS projection, clamped only for the DOS field;
- Info-ZIP extended timestamp `0x5455` with one signed 32-bit Unix mtime.

Therefore exact second-precision values within signed-32-bit Unix range are
lossless. Subsecond/declaration precision is truncated to seconds and reported
as `TIMESTAMP_PRECISION_LOSS`; out-of-range seconds are clamped and reported as
`TIMESTAMP_RANGE_LOSS`. Both require `--allow-lossy`.

## Deterministic bytes

Local headers contain final CRC/sizes, comments are empty, disk numbers are
zero, creator/required versions are fixed, and no clock, host, randomness,
source codec, or filesystem enumeration affects output. Generated bytes pass
Entrybound strict ZIP import.

Native `posix-metadata-v1` does not alter these frozen bytes. Symlink Entries
are `REFUSED`; hardlink topology and mode beyond the existing executable
projection, uid/gid, xattrs, and sparse layout are explicit `LOSSY` issues.
