# Deterministic tar export v1

Status: implemented and frozen as target profile `tar/pax-v1`.

## Entries and paths

The profile emits regular files and explicit directories in canonical EAM
LogicalPath order. UTF-8 paths use ustar `name`/`prefix` when exactly
representable; otherwise a per-entry POSIX pax `path` record carries the exact
path and the base header uses `PaxFiles/<16-lowercase-hex-ordinal>`.

Backslash and colon interpretations are refused. Pax, not GNU longname, is the
only long-path mechanism.

## Canonical headers

Construction fields are fixed and are not source ownership claims:

```text
uid = 0
gid = 0
uname = ""
gname = ""
regular non-executable mode = 0644
regular executable mode     = 0755
directory mode              = 0755
```

A source directory whose `core.executable` is false is consequently `LOSSY`
and requires explicit acceptance. Tar necessarily carries an mtime; absent
`core.mtime` is `LOSSY` and uses construction value zero.

## pax and timestamps

Second-precision, nonnegative mtimes fitting the 11-digit ustar octal field are
written directly. All other valid Entrybound timestamps use pax `mtime` with a
canonical decimal:

- second: no fraction;
- centisecond: 2 digits;
- microsecond: 6 digits;
- 100 ns: 7 digits;
- nanosecond: 9 digits.

Negative fractional times use their mathematically equivalent POSIX decimal.
Values inconsistent with their declared Entrybound precision are refused.
Files beyond the ustar size field use canonical pax `size`.

Pax keys are lexical, record lengths include their own decimal width, and
synthetic extended-header names are `PaxHeaders/<16-lowercase-hex-ordinal>`.
Headers use NUL-terminated zero-padded octal fields, unsigned checksums, exact
512-byte payload padding, and exactly two zero end blocks. No clock, PID, user,
host, or randomness enters output.

Generated bytes pass Entrybound strict tar import. Where the source semantics
are representable, strict re-import preserves LAI and exact file bytes.

Native `posix-metadata-v1` does not redefine this frozen profile. Symlink
Entries are `REFUSED`; hardlink topology, full mode/ownership, xattrs, and
sparse layout are explicit `LOSSY` issues even where the construction happens
to contain a compatible low-level field. Full POSIX export requires a future
versioned tar profile.
