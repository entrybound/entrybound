# Strict 7z import v1

Status: implemented and frozen as entrybound/sevenz-strict-v1.

## Boundary

The production path is 7z source bytes, independent structural observation,
the format-neutral Legacy Observation Model, strict reconciliation, EAM
regular files/directories, and ordinary native planning. No general 7z archive
library parses production structure or chooses semantic files. lzma-rust2,
flate2, and bzip2 are used only after Entrybound validates a bounded folder
graph and exact packed extent. sevenz-rust2 0.22.2 is an Apache-2.0,
test-only differential oracle.

## Signature and headers

Strict v1 accepts 7z version 0.0 through 0.4 with the six-byte signature at
offset zero. It validates the Start Header CRC over bytes 12..32, uses checked
arithmetic for the Next Header offset and size relative to byte 32, validates
the Next Header CRC, and requires the Next Header to end at EOF. A zero-length
Next Header is the canonical empty archive.

Both Header and EncodedHeader are supported. Encoded headers are decoded by
the same folder machinery as file data, must yield exactly one bounded
substream, and must decode to one complete plain Header. The LOM records the
packed extent, graph, decoded length, and decoded SHA-256. Header recovery by
signature scanning is intentionally absent.

## Streams and graph contract

The observer parses PackInfo, UnpackInfo, SubStreamsInfo, Folder coders, bind
pairs, packed input indices, coder output sizes, and all declared CRC vectors.
It constructs a graph from stream ownership and bind pairs rather than coder
record order.

The v1 executable graph is deliberately narrow:

- exactly one packed input;
- an acyclic connected chain of one-input/one-output coders;
- exactly one core coder directly consuming the packed input;
- at most one following simple filter;
- exactly one unbound final output.

Missing, multiply owned, cyclic, disconnected, or unexplained streams are
irreconcilable. Multi-input/output graphs and BCJ2 fail closed.

Supported core method IDs are COPY 00, LZMA 030101, LZMA2 21, BZip2 040202,
and raw DEFLATE 040108. Supported simple filters are Delta 03 and x86 BCJ
03030103. LZMA properties are exactly five bytes; LZMA2 properties are exactly
one byte and use the 7z dictionary formula. Delta uses one
distance-minus-one byte. x86 BCJ accepts no property or one little-endian u32
start position.

Unsupported methods report EB_7Z_UNSUPPORTED_CODER with their hexadecimal
method ID. This includes AES/encryption, PPMd, BCJ2, 7z Brotli/LZ4/Zstandard
extensions, and unknown methods.

## Solid folders and integrity

Each folder is decoded once. SubStreamsInfo partitions its exact final output;
the slices are then mapped in FilesInfo order only to entries not marked by
EmptyStream. EmptyStream plus EmptyFile denotes an empty regular file;
EmptyStream without EmptyFile denotes a directory. Every decoded byte and
every substream must be assigned exactly once.

Entrybound validates every present CRC authority: packed-stream CRC, folder
CRC, inherited single-substream CRC, and explicit substream CRC. Conflicting
sizes, stream counts, or CRCs fail strict reconciliation. Bytes enter EAM only
after all applicable integrity checks succeed.

## FilesInfo, paths, and metadata

Names are external-flag-zero UTF-16LE, NUL-terminated exactly once per file.
Malformed UTF-16, count mismatches, or embedded-NUL ambiguity fail. Slash and
backslash are both interpreted as 7z path separators, matching archives
generated by 7-Zip 26.02; rooted, drive/UNC, empty, dot, dot-dot, duplicate,
and file-as-ancestor paths are refused rather than normalized. Missing safe
directory ancestors may be synthesized and are recorded as Omission
resolutions.

Strict v1 projects only regular files, empty files, and directories. Anti
items, POSIX symlinks/FIFOs/devices, and Windows reparse/junction attributes
are unsupported. A compatible high-word POSIX mode can provide executable
bits; modification FILETIME maps to core.mtime at 100 ns precision.
Creation/access times, Windows attributes beyond the supported interpretation,
StartPos, and unknown bounded FilesInfo properties remain LOM and
FidelityReport evidence.

## Resource policy

SevenZImportPolicy independently limits source and Next Header bytes, decoded
header bytes, files, folders, coders, coder streams, packed streams,
substreams, coder property bytes, packed input, folder/file/total output,
expansion ratio, LZMA dictionary memory, and observation/conflict/resolution
counts. Declared output and dictionary requirements are checked before decoder
allocation; actual output remains bounded while decoding. Solid folders cannot
bypass archive-wide output limits.

## Provenance and identity

ConversionProvenance type 28 records source format 7z, adapter
entrybound/sevenz-strict-v1, exact source SHA-256, structural counts,
automatic resolutions, synthesized ancestors, unsupported metadata, and
outcome. Foreign representation evidence contributes to AUX only. For the same
projected EAM and native chunking, 7z versus another foreign encoding does not
change LAI or PCR; physical native encoding controls PCI.

## Differential evidence

The v1 probe reference is official 7-Zip 26.02 (2026-06-25). Generated COPY,
LZMA, LZMA2, BZip2, DEFLATE, solid LZMA2, encoded-header, Delta+LZMA2, and
x86-BCJ+LZMA2 archives produced identical restored SHA-256 values through
7-Zip and Entrybound. A separate generated LZMA2 case is continuously checked
against sevenz-rust2 0.22.2.

Malformed cases remain strict evidence for a future compatibility-profile
matrix; no runtime is spawned by production code.

## Unsupported v1 features

Encrypted headers/content, PPMd, BCJ2, arbitrary graphs, multi-volume archives,
anti-item projection, alternate streams, links/special files, compatibility
profiles, preservation, and 7z export are outside v1.
